# Consumer evaluation

These original synthetic briefs were frozen before the version 2 replacement was implemented. They are now public regression inputs, not unseen tests. Automated repository tests cover represented invariants; this manual evaluation checks whether an actual agent uses the library to produce source-faithful plans and useful behavior.

Use a fresh producer context and isolated consumer workspace containing the installed package, one original brief and the ordinary request. Supply only generic host transport and actual retained instruction metadata. Keep prior plans, reports and scoring guidance out of the producer context. An actual distinct reviewer compares original obligations with raw behavior, including plausible wrong behavior. Separate contexts/directories do not create OS isolation.

| Brief | Ordinary request | Required observation |
| --- | --- | --- |
| [A: archive preparation](brief-a.md) | Use ai-prompt-library to plan the supplied brief. Stop after planning and validation. | Faithful local/retained/live targets, quote producer before acceptance, scoped missing authority, preserved planning stop. No live operation. |
| [B: daily meter ledger](brief-b.md) | Use ai-prompt-library to implement the supplied brief and validate the result. | Actual external consumer, exact partitions/accounting, deterministic duplicates/reordering, invalid-input preservation, publication interruptions and retry, usable handover, independent selected release. |

Freeze the package/hash, original sources, host setup and first candidate before feedback. Retain failures and subsequent repairs separately. Use at most one external product repair round per run; self-corrections before review remain visible. A repeated brief after a library fix is a descriptive replication, not another unseen-domain success. Never turn a prior failing first attempt into a first-pass success.

The host must authenticate actual instructions, observations and reviewer responses against current bindings. A generic registry used by a real coordinator is integration infrastructure, not product guidance; its setup, dispatch, waiting, review and repair costs still count. Unit-test simulated receipts cannot supply real product acceptance. Do not relabel producer-authored receipts or permissive adapters as independent authentication.

Report separate structural, source-semantic, execution, consumer/recovery and release results. Intentionally omit a source obligation on a copy: structural validity may pass, but the actual source review must reject it. A high average score cannot cancel a material wrong-target, authority or recovery failure. No token/cost/reliability claim follows without matched controls and measured total effort.

The dated [validation report](../docs/validation.md) records observed results and limits. Raw local evidence retained during that run is identified by hashes in its parent project archive; it is not bundled into the npm package. Use new frozen briefs for future generalization claims.
