# Product Vision

Load only when clarifying product intent helps the selected slice. Write a concise `product-vision.md` inside the selected run, based on original requirements and verified source context.

Name the product, actual actors/consumers, problem, first valuable observable result, real entry, important constraints, success/recovery acceptance and explicit non-goals. Preserve all requested outcomes in the manifest ledger; do not redefine scope through a narrower vision. Record unknown assumptions. Infer the smallest supported platforms/capabilities; accounts, admin, monetization and mobile stores are not generic defaults.

The vision guides a representative proof, not exhaustive epic/feature decomposition. Any design or scope decision needs authority recorded in the contract. At a declared user checkpoint present meaningful choices and source-backed recommendations, then stop if required. Execution permission does not imply acceptance of the resulting product.
