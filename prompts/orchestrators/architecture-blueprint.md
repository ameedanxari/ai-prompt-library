# Architecture Blueprint

Load on demand for the active slice, a concrete high-risk decision, or an explicit architecture-only request. Read the versioned outcome manifest, verified source context, relevant existing composition and conditional source ledger. Do not require all-project features/tasks before making a useful architecture decision.

Record `architecture.md` in the selected run: actual targets and entry points; bounded contexts/canonical state ownership; interfaces and data flow for the proof; provider/configuration and persistence; authorization/security/privacy and applicable safety; failure/recovery; deployment/operation assumptions; concrete uncertainties and decisions. Preserve existing architecture unless a supported change is needed.

For regulated/cloud/high-stakes claims apply `.ai-prompts/prompts/orchestrators/research-and-fanout-policy.md`: current primary sources, jurisdiction, fail-closed workflows, audit, event ordering/idempotency/replay, data residency and workflow-specific RPO/RTO where applicable. Do not invent compliance or financial/legal approval.

Design enough real composition to expose integration risks in the first proof. Avoid speculative architecture for every deferred outcome. Keep implementation detail within the shared planning budget. Unknowns stay explicit; narrow the slice rather than manufacture requirements. Bind consequential architecture decisions to source/decision provenance. The manifest, not this document, retains authoritative scope and acceptance.

At required checkpoints present the architecture and unresolved decisions. Architecture-only authorization stops after that deliverable. A diagram/prototype cannot establish production integration or release readiness.
