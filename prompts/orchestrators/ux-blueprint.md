# UX Blueprint

Load for an actual visual surface in the active slice. Use the manifest, relevant source/reference context, existing UX and architecture; do not require all future feature files. Write concise `ux-flows.md` inside the selected run.

Specify the real entry-to-value sequence, actor intent, navigation, primary action, content hierarchy, trust/domain fit and meaningful fresh/populated/empty/loading/error/recovery states. Follow links and fallbacks, not only happy-path screen names. Account for relevant roles, representative sizes/devices, keyboard/assistive access and privacy/consent. Preserve all required outcomes in the ledger while detailing the proof only.

Inspect actual authoritative visual references before claims about them; preserve brand/source constraints and record approved deviations. If inaccessible, report uncertainty and develop a reviewed original direction within authority. Never fabricate inspiration or approval.

Components/tokens support composition; do not block all screen work behind an exhaustive design-system phase. Include actual composed-screen captures and relevant recovery evidence on the tested target. A component catalogue/palette or prototype cannot establish acceptance of the shipped journey. Content/composition changes stale affected acceptance. Honor declared checkpoints and owner/independent review provenance.
