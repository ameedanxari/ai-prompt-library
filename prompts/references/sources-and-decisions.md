# Sources and decisions

Start with what the user asked and the original evidence. Distinguish owner requirements, observed behavior, accepted decisions, supported inference and unknown facts. A derived summary is useful context but cannot supersede its original source.

Work through materially distinct originals before the plan: preserve concrete input → action → result, actor, qualifiers and target. Compare editions on behavior, dates, money, acceptance and deployment duties; check equivalent renderings before reusing an extraction. Distinguish an accepted choice from a recommendation or unresolved reserved choice in the same document. Retain foundations needed now for later capability without confusing deferred activation with permission to omit those seams. Same feature names or IDs can conceal different behavior. Record unread/partial sources and contradictions; inspecting originals is necessary but does not itself establish complete coverage. Compare both directions: every material original obligation has a disposition, and every planned capability has justification.

Use canonical requirements as the source-obligation ledger: split material behaviors and qualifiers into reviewable records, locate the original clause, and link observable acceptance and its release disposition. Retain conflicts, uncertainty and deferred duties explicitly; do not compress them into a feature label or discard them to fit an estimate. The source comparison in the public review packet places each source's declared obligations beside their linked acceptance, target and release closure. Work source by source from the original text, including sources with no mapped obligations. An independent reviewer must look for clauses omitted from the ledger entirely and describe a plausible wrong implementation the criteria still allow. The index is navigation, not a semantic verdict: matching links or filled records do not prove coverage.

Choose small reversible defaults when evidence supports them. Record an assumption only if its impact or revisit condition matters. Reuse stable accepted inputs. A contractual conflict, price, legal promise, irreversible action or reserved owner choice needs real authority; a broad document adoption does not close an explicitly open decision. For each material transitive prerequisite, trace it to the original obligation and explain why it is necessary for the requested completion boundary; preserve independent later duties without making them prerequisites unless the source requires it. Missing access is an input/resource, not a preference. Name its supplier and affected producer/consumer; do not block independent local work on a resource it does not use. A verified no-change result can complete its read-only consumer without mutation authority or another approval.

Ask the owner in plain language: what decision, why now, recommended option, meaningful alternatives and exactly what it blocks. Derive this brief from the canonical decisions/resources rather than maintain another register. An inspection or quote must be allowed to produce the result the owner later accepts.

Research only claims whose current correctness affects the decision. Prefer official documentation, original standards or regulators for their facts, and local sources for product commitments. Retain URL/date or file binding, extracted fact, uncertainty and influenced decision. Do not infer compliance from mentioning a framework. Inaccessible sources remain unknown. Split a large corpus by independent questions when useful, reconcile disagreements, and avoid repeating every extractor's prose.

For a replacement, inventory each material reported capability's actor, input/state, authorized effect and denial/recovery. Inspect accessible current routes, state, interfaces, configuration and tests, retaining relevant file/locator bindings. Distinguish observed code from observed runtime and from reported behavior; keep the baseline unverified where inspection is missing. Compare legitimate current behavior when access becomes available and disposition changes against adopted authority without assuming unsafe old permissions must persist. An inspection producer delivers its own report and recovery before a decision or replacement consumer needs it; missing access does not block independent preparation. Refresh relevant source and code bytes before current detail review and after changes; historical inspection cannot authenticate a different seam.

For substantial heterogeneous-source, replacement or authority work, follow the [native reviewer preparation/comparison sequence](../orchestrators/native-coordinator.md): the same distinct reviewer retains bounded source-located raw notes before plan exposure, then compares the packet and issues one scope judgment. Notes retain uncertainty and inspection limits, not a second requirements authority or completeness gate. Review originals absent from both notes and canonical IDs when material; neither inventory defines the entire scope.

On repair compare each affected original clause, previous acceptance and current replacement, then trace changed prerequisites to their consumers, actual provider/recipient proof and all affected targets. Preserve prior counterexamples and inspect change/no-change branches. Revisit relevant current bytes and prior material coverage gaps rather than only closing named findings; unchanged unrelated inputs do not demand ritual rereading. New estimates or dependency splits must not discard earlier acceptance.
