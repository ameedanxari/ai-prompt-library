# Consumer proof and recovery

Choose the real consumer: user route, installed command, SDK caller, API client, artifact reader or operator procedure. Exercise entry/setup → useful result → reachable failure/recovery on the actual composition. A test importing a mocked module cannot prove installation, provider integration or operations. Keep controlled-provider evidence labelled and retain real-integration obligations.

Make checks executable before claiming them. Confirm runner roots, includes/excludes, actual test file ownership, fixture/bootstrap configuration and required resources. Substantive suites must collect tests. Retain the command, exit status, actual collected counts and raw results; do not relabel plain output as JUnit or fabricate passing counters. Required build/package checks must run the product's real production build, not merely a syntax/typecheck substitute.

Use valid controls and one-defect negatives so a failure demonstrates the intended boundary. Test semantic wrong behavior while retaining IDs: wrong recipient, wrong tenant, duplicated effect, missing restored files or an operation that never reaches its consumer. Structural validation cannot discover omitted source meaning by itself.

When a harness fails, inspect its actual logs/artifacts and distinguish infrastructure failure from a product/test defect. For port conflicts choose an isolated configured port; for a corrupted tool cache invalidate only that cache. Reinstall heavy browser/runtime dependencies only when the diagnosed failure needs it. Do not delete all dependencies as a routine retry. A snapshot mismatch requires judgment about the expected result rather than automatic acceptance. Repeated unchanged failures need a new diagnosis, not a longer retry loop.

Retain honest missing, failed and unrun checks. Fix the cause instead of weakening assertions. At handoff include setup/actions, observed outputs, raw evidence, limits and next unblocker. Release proof covers the complete selected original scope, the current candidate and operator/handover obligations.

For owner-facing plans, retain concise source-derived amounts, payment or milestone triggers, feedback versus acceptance, decision-by points, affected work and explicit unknowns in canonical owner summaries and decision descriptions. Compare the brief with original commercial sources, not only the populated summaries; an omitted term remains a finding. A proposed effort estimate does not narrow required scope, and an actual source budget remains a visible constraint. In the source comparison, inspect missing producer work and existing evidence separately; neither alone proves acceptance.
