# `prompts/outputs/` — engine outputs

Everything in this tree is **generated** by the library's engines. Do
not hand-edit files here and do not commit them to a consumer project
— they are per-run artefacts.

## Subdirectories

| Subdirectory | Producer | Contents |
|---|---|---|
| `current/` | drill-down-engine, audit-and-remediate, revise-outputs, executor | The active run's artefacts: `project-context.md`, `epics.md`, `brief-keywords.md`, `features-*.md`, `external-accounts.md`, `tasks-*.md` / `remediation-*.md`, `audit-report.md`, `gap-list.md`, `revise-report.md`, `execution-log.md`. |
| `self-maintain/` | self-maintain orchestrator | The library's own self-audit output. Kept separate from `current/` so a maintainer run never collides with an end-user project run. |
| `field-tests/` (optional) | humans or consumers | Free-form observation files used as input to the self-maintain flow (`YYYY-MM-DD-run-name.md`). See `prompts/orchestrators/self-maintain.md` for the format. |

## Canonical artefacts

Two files in `current/` are **machine-produced** and must never be
hand-written:

- `revise-report.md` — produced by `scripts/revise.sh`. First line is
  always `---` (YAML frontmatter fence). The validator rejects
  narrative look-alikes.
- `execution-log.md` — produced by the executor. Carries the YAML
  handoff envelope that makes cross-session resume possible. Same
  frontmatter requirement.

## What you'll see during a run

Greenfield (`drill-down-engine`):

```
current/
├── project-context.md          # optional — only if working_copy/ had files
├── epics.md
├── brief-keywords.md
├── features-<epic>.md          # one per epic
├── external-accounts.md
├── tasks-<feature>.md          # one per feature
├── revise-report.md
└── execution-log.md
```

Gap-closure (`audit-and-remediate`):

```
current/
├── project-context.md
├── audit-report.md
├── gap-list.md
├── remediation-<gap>.md        # one per gap
├── external-accounts.md
├── revise-report.md
└── execution-log.md
```

## Rules

1. Do not mark a stage complete without the canonical artefacts named
   above — the validator will refuse to advance.
2. `revise-report.md` frontmatter must carry `executor_gate: pass`
   before the executor is allowed to start.
3. Any file under `current/` can be regenerated by re-running the
   relevant engine step; never rely on hand-edits surviving a rerun.
